# Parcel Manager — পার্সেল ও অর্ডার স্লিপ ম্যানেজমেন্ট

GitHub Pages-এ চলা স্ট্যাটিক ওয়েবসাইট (HTML + CSS + Vanilla JS), ব্যাকএন্ড **Supabase** (লগইন, ডাটাবেস, ছবি স্টোরেজ, রিয়েলটাইম সিঙ্ক)।
একটা অ্যাকাউন্ট দিয়ে ২–৩টা ফোনে একসাথে চলে। অর্ডার, সেটিংস, লোগো, QR সব Supabase-এ থাকে।

## ১. Supabase ফ্রি তো? (হ্যাঁ)

Supabase-এর **Free প্ল্যানে** এই অ্যাপ ভালোভাবে চলবে (কার্ড লাগে না)। ফ্রি প্ল্যানে যা মনে রাখবেন:

- ডাটাবেস ৫০০ MB, ১০,০০০ পর্যন্ত মাসিক ইউজার (আপনার ১টা), দুটো অ্যাক্টিভ প্রজেক্ট।
- **৭ দিন একদম ব্যবহার না হলে প্রজেক্ট পজ** হয়ে যেতে পারে। Supabase ড্যাশবোর্ড থেকে "Restore" চাপলেই চালু হয়। নিয়মিত অ্যাপ খুললে সমস্যা নেই।
- ফ্রি প্রজেক্টে অটো-ব্যাকআপ নেই। তাই মাঝে মাঝে **Order History → Export CSV** করে রাখুন।
- দাম ও লিমিট বদলাতে পারে। দেখে নিন: https://supabase.com/pricing

## ২. Supabase প্রজেক্ট বানানো

1. https://supabase.com এ গিয়ে **Start your project** → GitHub বা ইমেইল দিয়ে সাইন আপ।
2. **New project** → নাম দিন (যেমন `parcel-manager`), একটা শক্ত **Database Password** দিন (কোথাও লিখে রাখুন), Region হিসেবে **Singapore** (বাংলাদেশের সবচেয়ে কাছে) বেছে **Create** চাপুন। ১–২ মিনিট অপেক্ষা করুন।

## ৩. SQL চালানো (খুব গুরুত্বপূর্ণ ধাপ)

> **ক্রমটা মানুন:** আগে SQL চালান, তারপর নিজের ইউজার বানান। তাহলে আপনি অটোমেটিক মালিক (owner) হবেন।

1. বাম মেনু → **SQL Editor** → **New query**।
2. `supabase/schema.sql` ফাইলের **সব লেখা** কপি করে পেস্ট করুন → **Run**। নিচে "Success" দেখাবে। (আবার চালালেও সমস্যা নেই।)

## ৪. আপনার একমাত্র অ্যাকাউন্ট বানানো ও সাইনআপ বন্ধ

1. **Authentication → Users → Add user → Create new user**
   ইমেইল ও পাসওয়ার্ড দিন, **Auto Confirm User** টিক দিন → Create।
2. **Authentication → Sign In / Providers** (বা Settings): **"Allow new users to sign up"** বন্ধ (disable) করে Save করুন।
   এরপর কেউ নিজে অ্যাকাউন্ট খুলতে পারবে না।
3. (অতিরিক্ত নিরাপত্তা) ডাটাবেস নিজেও শুধু প্রথম ইউজারকে অ্যাক্সেস দেয়। পরে কোনো ইউজার ভুলে তৈরি হলেও সে কিছু দেখতে বা বদলাতে পারবে না।
4. দেখে নিতে SQL Editor-এ চালান: `select email, role, is_active from public.profiles;`
   আপনার ইমেইলের পাশে `owner` ও `true` থাকার কথা।

> যদি SQL চালানোর **আগেই** ইউজার বানিয়ে ফেলেন, তবুও চলবে। schema.sql আগের ইউজারকে অটো owner করে দেয়।

## ৫. Key ও URL বসানো

1. Supabase → **Project Settings → API** (বা "Data API / API Keys")।
2. কপি করুন:
   - **Project URL** (`https://xxxx.supabase.co`)
   - **Publishable key** (`sb_publishable_...`) অথবা পুরনো নামে **anon public** key।
3. `js/config.js` খুলে দুটো জায়গায় বসান:

```js
SUPABASE_URL: 'https://xxxx.supabase.co',
SUPABASE_KEY: 'sb_publishable_xxxxxxxxxxxx',
```

> ⚠️ **কখনোই** `secret` বা `service_role` key এখানে বসাবেন না। Publishable/anon key প্রকাশ্য হলেও নিরাপদ, কারণ ডাটাবেসে Row Level Security চালু আছে (লগইন ছাড়া কেউ কিছুই পড়তে বা লিখতে পারে না)।

## ৬. GitHub-এ আপলোড

1. https://github.com এ **New repository** → নাম `parcel-manager` → **Public** (ফ্রি GitHub Pages-এর জন্য) → Create।
2. রিপোজিটরি পেজে **uploading an existing file** লিংকে ক্লিক করুন।
3. `parcel-management` ফোল্ডারের **ভেতরের সবকিছু** (`index.html`, `css`, `js`, `assets`, `supabase`, `README.md`) টেনে এনে ছাড়ুন। `index.html` যেন রিপোজিটরির একদম উপরের স্তরে থাকে।
4. **Commit changes** চাপুন।

## ৭. GitHub Pages চালু

1. রিপোজিটরি → **Settings → Pages**।
2. **Source: Deploy from a branch**, Branch: **main**, Folder: **/ (root)** → **Save**।
3. ১–২ মিনিট পর উপরে লিংক আসবে: `https://আপনার-ইউজারনেম.github.io/parcel-manager/`
4. সব ফোনে এই লিংক খুলুন। ফোনে **"Add to Home screen"** করলে অ্যাপের মতো চলবে।

## ৮. প্রথমবার লগইন ও শপ সেটআপ

1. লিংক খুলে ধাপ ৪-এর ইমেইল ও পাসওয়ার্ডে লগইন করুন।
2. ড্যাশবোর্ডে হলুদ বার দেখাবে → **Shop Settings** খুলুন।
3. পূরণ করুন: দোকানের নাম, ট্যাগলাইন, প্রেরকের মোবাইল ও ঠিকানা।
4. **Upload Logo**-তে লোগো দিন।
5. **Upload QR Image**-এ **আপনার নিজের Facebook Page QR ছবি** দিন (PNG/JPG/SVG, ২ MB পর্যন্ত)। অ্যাপ নতুন QR বানায় না, আপনার ছবি হুবহু ব্যবহার করে, কাটে না, টানে না, রং বদলায় না।
6. **Save / Update Settings** চাপুন, তারপর **Preview Label** দিয়ে দেখে নিন।
7. ছবি আপলোড হওয়া মাত্র সেভ হয়ে যায়। বাকি লেখাগুলোর জন্য Save চাপতে হয়।

লেবেলের মাপ বদলাতে Settings → Label Size (ডিফল্ট 100 × 150 mm)।

## ৯. প্রতিদিনের ব্যবহার

- **New Order**: তথ্য ও পণ্য দিন → **Save Order**। সেভের আগে "Not Saved" দেখায়। সেভ হলে ডাটাবেস **SP-BW + ৬টা র‍্যান্ডম সংখ্যা** (যেমন SP-BW583921) দেয়।
- **PRINT LABEL**: ব্রাউজারের প্রিন্ট ডায়ালগ খোলে, শুধু লেবেল ছাপে।
- **DOWNLOAD PDF**: আসল PDF ফাইল নামে (`SP-BWxxxxxx.pdf`) ডাউনলোড হয়, ১০০×১৫০ mm।
- **Order History**: সার্চ (Order ID / নাম / মোবাইল), তারিখ ফিল্টার, এডিট, ডুপ্লিকেট (নতুন ID), ডিলিট (কনফার্মসহ), CSV এক্সপোর্ট।
- এডিট বা রিপ্রিন্টে Order ID **কখনো বদলায় না**।
- ডিলিট করা অর্ডারের ID আর কখনো নতুন অর্ডারে দেওয়া হয় না।

## ১০. মোবাইল থেকে প্রিন্ট: সীমাবদ্ধতা (সৎ কথা)

ব্রাউজার থেকে প্রিন্ট করা যাবে কি না, নির্ভর করে প্রিন্টারের কানেকশনের ওপর:

| প্রিন্টার | মোবাইল ব্রাউজার থেকে সরাসরি প্রিন্ট |
|---|---|
| Wi-Fi / Ethernet থার্মাল প্রিন্টার (AirPrint / Mopria / IPP সাপোর্ট) | ✅ সবচেয়ে ভালো |
| প্রিন্টারের নিজস্ব অ্যাপ বা প্রিন্ট সার্ভিস প্লাগইন আছে (Android) | ✅ প্রিন্ট ডায়ালগে প্রিন্টার দেখায় |
| শুধু Bluetooth / USB, ব্রাউজার থেকে দেখা যায় না | ❌ সরাসরি হবে না |

যদি সরাসরি না হয়: **DOWNLOAD PDF** করে PDF-টা প্রিন্টারের নিজস্ব অ্যাপ (যেমন Munbyn, Phomemo, NetPrinter ইত্যাদি) দিয়ে খুলে প্রিন্ট করুন। PDF এর পেজের মাপ ঠিক ১০০×১৫০ mm, তাই ৪×৬ ইঞ্চি লেবেল রোলে মিলে যাবে।

প্রিন্ট ডায়ালগে ঠিক করে নিন: **Paper size = 100×150 mm (বা 4×6 in)**, **Margins = None**, **Scale = 100% / Actual size**। Headers & footers বন্ধ।
কম্পিউটারে Chrome ব্যবহার করলে এগুলো সহজে ঠিক করা যায়।

## ১১. PDF ও বাংলা: কীভাবে কাজ করে

- PDF সম্পূর্ণ ব্রাউজারেই তৈরি হয় (pdf-lib), প্রিন্টারের ওপর নির্ভর করে না, আর "Save as PDF" ডায়ালগও খোলে না।
- বাংলা যুক্তাক্ষর ও কার-চিহ্ন ঠিক রাখতে লেবেলের লেখা ব্রাউজার নিজে আঁকে (৬০০ dpi পর্যন্ত) এবং PDF পেজে বসায়। তাই PDF-এর **লেখা ছবির আকারে**, সিলেক্ট বা কপি করা যাবে না। ছাপার মান তীক্ষ্ণ।
- **QR আলাদা ছবি হিসেবে** PDF-এ বসে। আপনার ছবির পিক্সেল হুবহু থাকে (শুধু পূর্ণসংখ্যা গুণে বড় করা হয়, ঝাপসা করা হয় না), তাই স্ক্যান হয়।
- বাংলা ফন্ট: স্ক্রিনে ও প্রিন্টে **Noto Sans Bengali** (Google Fonts থেকে লোড হয়)। ইন্টারনেট না থাকলে ডিভাইসের নিজস্ব বাংলা ফন্ট ব্যবহার হয়।

## ১২. রিয়েলটাইম সিঙ্ক ও স্ট্যাটাস

উপরের ডানদিকের ব্যাজ: 🟢 **Synced** (সংযুক্ত) · 🔵 **Saving…** · 🟡 **Connecting/Reconnecting…** · 🔴 **Offline**।
এক ফোনে অর্ডার বা সেটিংস বদলালে অন্য ফোনে কয়েক সেকেন্ডে আপডেট হয়। ব্যাজে ট্যাপ করলে জোর করে রিফ্রেশ হয়।
নেটওয়ার্ক না থাকলে সেভ ব্যর্থ হয় এবং অর্ডার "সেভ হয়েছে" দেখানো হয় না। আবার Save চাপলেও ডুপ্লিকেট অর্ডার হয় না।

## ১৩. Order ID কীভাবে তৈরি হয়

- `create_order()` ডাটাবেস ফাংশন সেভের সময় ID বানায়। ব্রাউজার ID বানাতে বা বদলাতে পারে না।
- র‍্যান্ডমনেস: PostgreSQL-এর নিরাপদ র‍্যান্ডম উৎস, পক্ষপাতহীন নমুনা।
- প্রতিটি ID `order_id_registry` টেবিলে চিরতরে সংরক্ষিত (ডিলিট করলেও)। `orders.order_id`-এও UNIQUE constraint আছে। সংঘর্ষ হলে নতুন ID নিয়ে আবার চেষ্টা হয়।
- ৬ ডিজিটে ১০ লক্ষ ID। জায়গা প্রায় ভরে এলে (১২ বার পরপর সংঘর্ষ) ডিজিট একটা বাড়ে (SP-BW + ৭ ডিজিট, সর্বোচ্চ ৯)। আগের ID অপরিবর্তিত থাকে।
- বর্তমান অবস্থা দেখতে (SQL Editor): `select count(*) from public.order_id_registry;`

## ১৪. নিরাপত্তা সারকথা

- সব টেবিলে Row Level Security চালু। `anon` (লগইনহীন) রোলের কোনো টেবিলে অ্যাক্সেস নেই।
- শুধু active প্রোফাইলওয়ালা ইউজার ডেটা পড়তে বা বদলাতে পারে।
- অর্ডার তৈরি ও এডিট শুধু ডাটাবেস ফাংশন দিয়ে, সরাসরি INSERT/UPDATE বন্ধ। তাই ID জাল বা বদল করা যায় না।
- ছবি আপলোডে ফাইলের আসল ধরন যাচাই (PNG/JPG/SVG), ২ MB সীমা, স্ক্রিপ্টওয়ালা SVG বাতিল।
- স্টোরেজ বাকেটের ছবি পাবলিক-পঠনযোগ্য (লেবেলে ছাপা হয় বলে), কিন্তু আপলোড/মোছা শুধু শপ মেম্বার পারে।
- ইউজারের লেখা সব টেক্সট `textContent` দিয়ে দেখানো হয় (XSS প্রতিরোধ)।
- CSV-তে `= + - @` দিয়ে শুরু হওয়া ঘরে সুরক্ষা (spreadsheet formula injection)।

## ১৫. সমস্যা হলে

| সমস্যা | সমাধান |
|---|---|
| "Setup needed" দেখাচ্ছে | `js/config.js`-এ URL ও Key বসান |
| লগইনের পর "shop data could not be loaded" | `supabase/schema.sql` চালানো হয়নি, চালান |
| "This account is not authorised" | `select * from public.profiles;` দেখুন। আপনার ইউজারের `is_active` false হলে: `update public.profiles set is_active = true, role = 'owner' where email = 'আপনার@ইমেইল';` |
| লেবেলে লোগো/QR আসছে না | Settings-এ আবার আপলোড করুন, ইন্টারনেট দেখুন |
| প্রজেক্ট ঘুমিয়ে গেছে | Supabase ড্যাশবোর্ডে **Restore project** |
| প্রিন্টে মাপ ভুল | প্রিন্ট ডায়ালগে 100×150 mm, Margins None, Scale 100% |
| পাসওয়ার্ড ভুলে গেছি | Supabase → Authentication → Users → ইউজারের ⋯ মেনু থেকে পাসওয়ার্ড রিসেট |
| অ্যাপ আপডেটের পর পুরনো দেখাচ্ছে | ব্রাউজারে হার্ড রিফ্রেশ (Ctrl+Shift+R) |

## ১৬. আপনার নিজের টেস্ট চেকলিস্ট (প্রথম ব্যবহারের আগে)

আমি আসল Supabase-এ কানেক্ট করতে পারিনি। নিচের জিনিসগুলো আপনার প্রজেক্টে একবার করে যাচাই করুন:

- [ ] লগইন হচ্ছে, ভুল পাসওয়ার্ডে এরর আসছে।
- [ ] লগআউট করে ফোন ২-এ একই ইমেইলে লগইন করা যাচ্ছে, দুই ফোনে একসাথে চলছে।
- [ ] ফোন ১-এ অর্ডার সেভ করলে ফোন ২-এ কয়েক সেকেন্ডে দেখা যাচ্ছে।
- [ ] ফোন ১-এ Settings বদলালে ফোন ২-এ বদলে যাচ্ছে।
- [ ] লোগো ও QR আপলোড হচ্ছে এবং দুই ফোনেই দেখা যাচ্ছে।
- [ ] বাংলা নাম/ঠিকানাসহ অর্ডার সেভ ও লেবেলে সঠিক দেখাচ্ছে।
- [ ] একটা টেস্ট লেবেল ছেপে **ফোন দিয়ে QR স্ক্যান** করে দেখুন আপনার Facebook Page খুলছে।
- [ ] **DOWNLOAD PDF** করা ফাইলের নাম Order ID-এর মতো এবং মাপ 100×150 mm।
- [ ] এডিট করলে ID একই থাকছে, ডুপ্লিকেট করলে নতুন ID আসছে।
- [ ] ডিলিটে কনফার্ম চাইছে।
- [ ] ইন্টারনেট বন্ধ করে সেভ চাপলে "Not saved" আসছে, ID তৈরি হচ্ছে না।

## ১৭. লাইব্রেরি ও অফলাইন

`index.html` দুটো লাইব্রেরি CDN (jsDelivr) থেকে লোড করে: `@supabase/supabase-js@2` ও `pdf-lib@1.17.1`।
এগুলো নিজের রিপোজিটরিতে রাখতে চাইলে ফাইল দুটো `vendor/` ফোল্ডারে ডাউনলোড করে `index.html`-এর `<script src>` দুটো বদলে দিন।
